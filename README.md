# Практическая работа: Введение в TypeScript

## Часть 5. Анализ ошибок компилятора

* **Код A:** `Type 'string' is not assignable to type 'number'.`
  * **Причина:** Переменная count выведена как number. Присвоение строки недопустимо.
  * **Исправление:** `count = 10;` или изменить тип на `number | string`.

* **Код B:** `Expected 2 arguments, but got 1.`
  * **Причина:** Функция add требует два аргумента.
  * **Исправление:** `add(2, 3);` или сделать второй параметр необязательным: `function add(x: number, y: number = 0): number`.

* **Код C:** `Type 'null' is not assignable to type 'string'.`
  * **Причина:** При strictNullChecks null не входит в тип string.
  * **Исправление:** `let name: string | null = null;` или `let name: string = "";`.

* **Код D:** `A function whose declared type is neither 'void' nor 'any' must return a value.`
  * **Причина:** Функция объявлена с возвращаемым типом string, но ничего не возвращает.
  * **Исправление:** Добавить `return "Привет, " + name;` или изменить тип на void.

## Часть 6. Вопросы для самопроверки

1. **Что такое статическая типизация и какие преимущества она даёт?**
   Это свойство языка, при котором тип переменной известен на этапе компиляции и проверяется до выполнения программы. Преимущества: раннее обнаружение ошибок, автодополнение в редакторе, самодокументируемость кода.

2. **Что такое вывод типов? Когда лучше указывать аннотацию явно?**
   Вывод типов — автоматическое определение типа компилятором на основе начального значения. Аннотацию лучше указывать явно для параметров функций, возвращаемых значений и при объявлении переменной без начального значения.

3. **За что отвечает "strict": true в tsconfig.json?**
   Включает все строгие проверки типов, включая strictNullChecks (запрет на присвоение null/undefined другим типам) и noImplicitAny (запрет на неявный any).

4. **Как скомпилировать проект и запустить результат?**
   Компиляция: `npx tsc`. Запуск: `node dist/index.js`.

5. **Почему null нельзя присвоить переменной типа string при strictNullChecks? Как правильно это сделать?**
   Потому что strictNullChecks делает null и undefined отдельными типами, которые не пересекаются с string. Правильно: `let str: string | null = null;`.

6. **Чем void отличается от undefined в контексте возвращаемого типа функции?**
   `void` означает, что функция ничего не возвращает (используется для побочных эффектов). `undefined` — это конкретное значение, и функция с типом `undefined` обязана вернуть это значение явно.

7. **Какую роль играют опции rootDir и outDir в tsconfig.json?**
   `rootDir` указывает, где лежат исходные .ts-файлы, а `outDir` — в какую папку складывать скомпилированные .js-файлы.
